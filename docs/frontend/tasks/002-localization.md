- **Исполнитель:** Frontend.
- **Статус:** ТЗ утверждено; выполняется после `FRONT-001`.
- **Основание:** перенос функционала локализации из проекта-исходника [nordelVPN/company_nordel-landing_Native](https://github.com/nordelVPN/company_nordel-landing_Native) (см. `src/modules/i18n.js`).
- **Готовый словарь и ключи:** [copy-and-locales.md](../copy-and-locales.md).

> **Поправка [`FRONT-003`](003-corrections.md).** Четыре тарифа `#plans`: второй — `Next - 1 month` / `Далее - 1мес`, цены `€1`, `€7`, `€15`, `€55`. Ключи `pricing.plans.0`…`pricing.plans.3` остаются. Строки модалки `Complete your order.` и страницы `account.html` берутся из `FRONT-003`. Переключение EN/RU без перезагрузки работает и на `account.html`.

## Задача

Реализовать единый модуль `src/modules/i18n.js`, переключающий интерфейс единого лендинга `index.html` (и любых будущих страниц) между **EN** и **RU** без перезагрузки. Английский (`en`) остаётся языком по умолчанию и совпадает с базовым статическим HTML (точные тексты с концептов).

Словарь переводов хранится в `src/data/locales.json`: верхний ключ — код языка (`"en"`, `"ru"`), внутри — плоский объект пар `"section.key": "text"`.

## Контракт разметки

- `data-i18n="hero.line0"` — заменяет текстовое содержимое конкретного элемента через `textContent`.
- `data-i18n-aria-label`, `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-content` — переводят соответствующий HTML-атрибут (включая `<meta name="description" data-i18n-content="...">` и `<input data-i18n-placeholder="support.searchPlaceholder">` в секции `#support`).
- `data-language-select` — `<select>` переключателя языка; пункты `<option>` заполняются программно из ключей словаря (`dictionaries[code]['language.name']`).
- **Сложные заголовки и кнопки с иконками:** текстовая фраза оборачивается в отдельный `<span>` с `data-i18n`; иконки, SVG и `<br>` остаются соседними узлами. Вставка сырого HTML из JSON запрещена (`innerHTML` не используется).
- **Повторяющиеся элементы (списки преимуществ, 4 тарифа, категории поддержки):** получают ключи с индексом, например `hero.features.0.title`, `pricing.plans.2.note`, `support.categories.0.title`.
- **Динамические компоненты (`app-preview.js` и др.):** используют функцию `t(key)` и подписываются на событие `languagechange` на `document` (`event.detail.language`), обновляя текущие надписи **без сброса состояния** (например, состояние подключения `Connected (preview)` должно сохраниться при смене языка).

## Техническая спецификация модуля `src/modules/i18n.js`

- Подключается **первым** в списке `modules` в `webpack/pages.js`.
- Экспортируемый API:
  - `t(key)` — возвращает перевод для текущего языка, при отсутствии ключа делает fallback на `en`, при отсутствии и в `en` возвращает `null`;
  - `translate(root = document)` — применяет переводы ко всем размеченным элементам внутри `root` (и к самому `root`, если он подходит под селектор);
  - `setLanguage(code)` — устанавливает язык (неизвестный код откатывается к `en`), обновляет `document.documentElement.lang`, вызывает `translate()`, синхронизирует все `[data-language-select]`, сохраняет выбор в `localStorage['n1x-language']` внутри `try/catch` и диспатчит `new window.CustomEvent('languagechange', { detail: { language } })` на `document`.
- При инициализации читает `localStorage['n1x-language']` в `try/catch`; при отсутствии доступа к storage использует `en` без ошибок.
- Словарь `src/data/locales.json` включается в бандл Webpack (`require('../data/locales.json')`); после изменения текстов требуется пересборка.

## Этапы реализации

1. Перенести готовый словарь `src/data/locales.json` (`en` и `ru`, 103 ключа) из [copy-and-locales.md](../copy-and-locales.md) и реализовать контроллер `src/modules/i18n.js` с fallback на `en`.
2. Разметить `data-i18n*` на всех фразах, заголовках, `<title>`, `<meta name="description">`, `placeholder`, `aria-label`, кнопках, `header`, `footer`, модальном окне вишлиста и интерактивном превью.
3. Обеспечить сохранение выбора в `localStorage['n1x-language']`, обновление `<html lang="...">`, восстановление после перезагрузки.
4. Проверить сборки, ESLint, переключение EN ↔ RU, динамическое превью, модальное окно вишлиста, вложенную разметку (сохранение SVG-иконок и обработчиков) и отсутствие горизонтального переполнения на `375 / 768 / 1440 px`.

## Границы и правила перевода

- Термин **«вишлист»** в русской версии не заменять на «лист ожидания» или `waitlist`.
- Бренд **N1X VPN** / **N1X** не переводится. Знак `€` у суммы один и тот же в EN и RU и стоит сразу перед числом. Строки тарифов и модалки заказа берутся из [`FRONT-003`](003-corrections.md).
- Переводы RU — рабочая редакция из [copy-and-locales.md](../copy-and-locales.md) до финальной вычитки маркетологом.
- Юридические ссылки `Privacy Policy` / `Terms of Use` остаются заглушками `href="#"`.
- Клиентское переключение языка не создаёт отдельных индексируемых URL (`/ru/`, `/en/`); многоязычная SEO-маршрутизация при необходимости выносится в отдельную задачу.

## Критерии приёмки

- [ ] Наборы ключей в `locales.json` для `en` и `ru` полностью совпадают (автопроверка).
- [ ] Перевод применяется мгновенно без перезагрузки на `index.html`.
- [ ] Переключение языка не сбрасывает состояние мобильного меню и состояние подключения в `app-preview`, не удаляет SVG-иконки и обработчики событий.
- [ ] Выбранный язык сохраняется в `localStorage['n1x-language']` и восстанавливается после перезагрузки; недоступность `localStorage` не вызывает ошибок.
- [ ] Неизвестный код языка безопасно заменяется на `en`; неизвестный ключ сохраняет исходный текст из HTML.
- [ ] При отключённом JavaScript пользователь получает полноценный английский HTML с точными текстами с концептов.
- [ ] На `375 / 768 / 1440 px` в обоих языках отсутствует горизонтальный скролл и обрезание текста; пройдены `npm run build:prod` и `npm run lint`.
- [ ] Ограничения и непроверенные браузеры (например, Firefox/Safari, если не прогонялись) честно фиксируются в QA-отчёте.
